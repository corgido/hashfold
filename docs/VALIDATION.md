**Read this first.** Small-N demonstration of the METHOD, not a production drift claim: the held-out documents are ~200-word segments of the same 8 prose fixtures whose even-parity segments calibrated the reference (segments of 8 documents are not independent samples), the calibration null has n=15, and the perturbations are mechanical surface edits, not a model of real LLM drift. The deliverable that scales is the user-run protocol: the same tool in --corpus-dir mode against the user's own reference and corpus. What the numbers below demonstrate is that the pipeline (reference → percentile → operating point → batch SPC) detects known injected changes at rates that track realized effect size, with a negative control at the nominal false-positive rate — on this corpus, at this size, for these mechanical edits. Treat every number as a property of the demonstration, not of your deployment; the user protocol below is how the same claim is earned on your own data.

## Method

- **Reference**: `fixtures/references/fixture_prose_v1.json` (`fixture_prose` `v1`, cohort `fixture_prose`, n=15, null basis `cross_validated_10fold`, sha256 `ecaba1aade94c94b07b5b89081ffd2a54fb8487d1739cfdd3fc1914fda2de9de`), built from the EVEN-parity ~200-word fixture segments (`tools.fixture_corpus`).
- **Held-out set**: the ODD-parity segments — same fixtures, disjoint text. Segments that fail to project or read below the measurement envelope are dropped and counted, never silently.
- **Perturbations**: the 8 mechanical edits of `tools/perturb.py`, applied at intensity ε ∈ {0.1, 0.25, 0.5, 1}; rng seeded per (document, perturbation, ε) as `validation:<perturbation_id>:<epsilon>:<input_sha256(unperturbed doc)>`.
- **Detection policy**: detected := reference_envelope.percentile > 95 — the illustrative 5% operating point (raw percentile/distance streams are in the JSON artifact, so any operating point can be recomputed). With an n=15 null, percentiles move in ≈6.7-point steps, so the achievable false-positive rates are coarse — another reason this is a method demonstration.
- **Effect size**: (median perturbed distance - median unperturbed distance) / sigma0, sigma0 = pstdev(reference self_distance.values) (σ₀ = 0.776, μ₀ = 1.423).
- **Intervals**: exact Clopper–Pearson 95% CIs (`instrument.kernel.stats.binomial_ci_clopper_pearson`).
- **Batch power**: per cell and batch size N, 100 DetRandom-resampled batches of N perturbed distances, each appended to a 30-point in-control prefix resampled from the reference null (seed `validation:power:<perturbation_id>:<epsilon>:<batch_size>`); power = fraction in which the EWMA chart (`instrument.spc.ewma`, λ=0.2, L=3) signals within the batch region.

## Limitations

- **Segment non-independence**: the held-out “documents” are segments of 8 fixtures; style repeats across segments of the same fixture, so the effective sample size is closer to 8 than to 11, and the CIs are optimistic in that respect.
- **Thin calibration**: the reference null has n=15; percentiles move in ≈6.7-point steps and the >95 operating point only fires beyond the null's upper tail. User references should be built on hundreds of documents (`docs/CALIBRATION.md`).
- **Mechanical ≠ model drift**: these perturbations move surface features the instrument measures; a model swap moves many features at once in correlated ways. Detection of one is evidence about the method, not a guarantee about the other.
- **Pooled cohort**: the reference pools all 8 fixture registers into one cohort, so its null is wide; register_mix moves documents *within* that pooled cloud, which bounds its realized effect size here.
- **Resampled batch power**: power figures resample the same ≤11 perturbed distances per cell; they are statements about the observed shift sizes, not new data.

## User protocol — the study that scales

The in-repo study is the rehearsal; this is the performance. To run the same validation on your own regime change (model swap, temperature, prompt template, decoding params):

1. **Calibrate on regime A**: collect ≥100 documents produced under the current regime; build a reference —
   `python -m tools.build_reference --corpus-dir regimeA/ --name my_baseline --cohort my_baseline --scope "..." --collection-window "..." --out refs/`.
2. **Capture regime B**: collect documents produced under the candidate regime into a directory of `.md` files (name them in time order if you want the SPC charts to read as a time series).
3. **Run the unperturbed analysis** (this tool, user mode):
   `python -m tools.validation_study --corpus-dir regimeB/ --reference refs/my_baseline_v1.json [--hint my_baseline] [--out report.json]`
   The report carries the percentile stream, the detection rate at the documented operating point vs nominal, and the EWMA/CUSUM/individuals chart summary — the same statistics as this study's negative control, on your data.
4. **Interpret with your n**: detection CIs are exact Clopper–Pearson at your document count, and batch power scales with your batch sizes — rerun step 3 on regime-A hold-outs to get your own negative control before you trust a positive.
5. **Ongoing monitoring**: stream production emissions to JSONL and chart them with `python -m tools.control_chart --emissions out.jsonl --reference refs/my_baseline_v1.json` (see `docs/INTEGRATION.md`).

The verdicts here are descriptive chart states, never actions: what to do when a batch signals (recalibrate, investigate, quarantine) is the user's out-of-control action plan (`instrument/spc.py`).
